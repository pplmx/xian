# 炼丹体系设计备忘

这份文档记录"为什么这颗丹这么定价、为什么这张方子这么难"—— 数值口径见
[usage.md](./usage.md) 的数值小节与 `src/core/pillValue.ts`,本文件只写**设计
上的取舍与边界**。

## 审计口径(怎么比才不算错)

全部丹药放进同一张表(`core/pillValue.spec.ts` 打印,断言守着九条法则):

- **药力统一折成等效挂机秒数**,并在**各自准入境界**取值 —— 同一枚聚气丹在炼气期
  抵半层修为、在化神期连一次呼吸都不到,不统一境界比出来的是境界差不是丹药差。
- **掉落品与可炼品各算各的账**:白捡的代价是稀有度(多少场见一枚),可炼的代价才
  是灵草、灵石与炸炉赔的料。跨线只比药力绝对值。
- **跨族不可比**:寿元按绝对年数不贬值、悟道按藏经阁速率、修速按 buff 窗口折算,
  各轴随境界走势不同,只在族内横向比较。

## 九条法则(A–H + I/I2)

头八条(A 掉落不过六成 / B 品质单调 / C 增益唯一 / D 固定点数只入门 / E、E2 掉落池
非空且非入门堆砌 / F 满额回资源须可炼 / G 修为丹按时长计价 / H 掉落不压可炼顶端)
长期守住"白捡的不比炼的强"。本轮新增两条:

- **I 可炼难度契约**:每张可炼方在其**准入境界处** overReach ≤ 1。bearableRank(境界)
  = 境界 + 1,而 minRealm 就是这方子"该出场"的境界 —— 它若在自己该出场的境界还要
  越两级强炼,等于逼玩家要么等反超、要么赌命。审计曾抓出 6 味关键丹挂 24% 成功率
  (破境/延寿/千年/万寿/悟道/太虚),回拨档位后统一到 41%。「越阶强炼」留给 over=1
  那一档:超一阶尚有一搏。
- **I2 内容厚度契约**:五条可折算时间的可炼线,每条 ≥3 味。修速族曾只有精品聚灵
  与神品本源两端、1~17 境全空 —— 玩家中期唯一的选择是白捡的造化丹。补星驰(玄 4)
  与御风(地 6)之后,修速可炼线 4 味、药力随品阶递进(15 < 18 < 22.5 < 24 分)。
  定价特别盯着**单位材料性价比**:开局聚灵 14 草换 15 分是全家族最超值的 outlier,
  若新丹走 45/85 草的"高规格高价格"路线,就是两味没人炼的填充物。星驰/御风刻意
  压草耗(24/30)、抬强度(60%/75%),使单位材料性价比(≈3.7/3.5)反超聚灵 ——
  玩家到 4/6 境有十足理由换一味更强的。
  附注:多味修速 buff 可叠加(聚灵+星驰+御风+本源 ≈ +265%),这是既存的跨 buff
  叠加设计(单 buff 只有 2 倍时长上限,见 consumableBuffCap),全靠"炼丹成本"兜底
  —— 价格若松,这一族就会变成白嫖修速;I2 的代价契约正是第一道闸。

## 明确不动的边界(勿在无新理由时重开)

- **灵乳 / 仙泉玉液 / 神泉 / 道泉**:一口回满灵气是"战术最锋利的即时效果",设计上就该
  贵而稀有(灵乳单位成本 = 回灵丹的 1.97 倍,有测试钉着一到三倍)。审计折算口径天然
  低估它 —— 那不是失配。
- **本源丹**(修速可炼顶端,性价比折算 0.24 全表最低):它带着 `breakthroughRate +10%`
  这张战术底牌,折算口径不建模;且它已是可炼线顶端(品阶/药力序都正确)。
- **造化丹**(天品掉落却弱于精品聚灵):与奇遇系统共用 `bless_daoyun`,改数值波及
  events 十余处,是既存账,见 pillValue.spec「未处置的账」。
- **掉落池 0~2 境只有妖血丹**:法则 E 证明可掉,池窄是内容缺口 —— 下一步是加丹,
  不是改妖血丹的数值。

## 炼丹的自增益(体系吃自己的药)

- **火候丹**(双成概率 +20%):`alchemyYield` 词条直连 `engineCraft.alchemyBonus`。
- **淬炼丹**(炼丹心得 +30%):新增 `craftExpGain` 词条,在 `pillService.gainCraftExp`
  处把开炉得的技艺经验 ×(1 + craftExpGain)接线上 —— 「做得多就精」的那份"更多",
  此刻可以来自泉涌的心得,而不只是开炉次数。
- **尚未做:炸炉减损**(保料比例提升)。方向已明,须为每个新词条过 `fruitOutlets`
  的"StatMods 全命名空间可达效率链"红线(新词条要登记效率路径,否则该红线即红);
  这条不免费,别顺手跳过。

已登记并守护:`craftExpGain` 走通了 `types` 联合 → `statNames` 显示名 →
`fruitOutlets.VIA_RESOURCE` 效率路径 → `pillService` 消费 四处接线,并被
pillValue/dataIntegrity/vocabularyCoverage/fruitOutlets 四道门验证。
